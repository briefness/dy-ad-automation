# 本地素材工作流

本地素材模式不会调用可灵生成画面。它先理解用户提供的完整素材集，再根据素材证据生成可执行的带货脚本、单条口播和选片计划。

## 执行顺序

```text
素材分窗与视觉理解
        ↓
产品实体与素材实体关联
        ↓
素材角色、可用容量和自然时间轴
        ↓
Material Copy Contract
        ↓
证据约束脚本与单条口播
        ↓
脚本预检与素材能力重落地
        ↓
非重复优先的语义选片
        ↓
字幕、贴图、BGM、转场和最终导出
```

脚本生成和镜头选择不会分别理解一套素材。二者共享素材角色、`primary_visuals`、Evidence Anchor 和容量统计。

## Material Copy Contract

### 视觉能力

只有连续至少两帧清晰可辨、处于主要位置或承担主要动作，并足以独立承载一句字幕主张的主体及动作，才进入 `primary_visuals`。背景偶然出现、模糊对象和极短闪现可以保留为上下文，但不能成为文案模型的主要视觉选择。

### 事实边界

事实来源按可信度分为：

1. 使用者提供并确认的产品资料。
2. 包装、标签或素材中清晰可读且与产品实体相关的信息。
3. 与产品实体建立了明确关系的素材情境。
4. 仅用于理解画面的普通视觉描述。

产品名称只证明身份。具体产地、原料、工艺、规格、品质和功效必须由相关证据支持。

### 有边界的关联

系统允许适当联想，但不允许无限推导：

- 包装标注某种原料，素材又清晰出现对应实体，可将其识别为原料情境。
- 对应植物的种植园、农场、山地或水域环境，可识别为产地情境。
- 上述情境不能单独证明具体地名、海拔、等级、口感因果、健康功效或品质优越性。

这一规则由实体类别和关系强度决定，不写死具体产品、植物或品类。

### 营销责任

- `hook`：建立具体悬念或选择冲突。
- `value`：必须给出消费者购买理由，并由可信事实或真实使用结果支持。
- `proof`：呈现来源、原料、工艺或其他可信证明，不把画面描述假装成卖点。
- `cta`：在购买理由成立后自然推动了解或尝试。

系统会从最终文案和证据推导 `visual_binding`、`visual_claim`、`marketing_device` 和 `buyer_value`，而不是要求 LLM 重复返回多份容易冲突的元数据。

## 时长与选片

未指定 `--target-duration` 时，素材自然容量和单条 TTS 时长决定时间轴。显式指定时，系统会尽量规划到目标时长，但不会：

- 循环同一素材来补足时长；
- 拉伸短镜头到明显卡顿；
- 使用语义无关的镜头；
- 伪造素材中不存在的场景。

选片时优先使用未重复、主体清晰、语义相关且可用容量充足的时间窗。只有在全部独立素材不足时才考虑受控复用，并继续受语义合同约束。

## 语义贴图

贴图以脚本和字幕为语义入口，以可信产品事实和已选素材为证据。原料、产地、工艺等信息优先；普通操作描述、出行便利等没有独立信息增量的字幕不会因为出现于口播就自动成为贴图。

贴图会自动计算：

- 与字幕语义相关的展示时间；
- 主体、字幕和平台安全区之外的位置；
- 适合当前画面的配色和轻微动效；
- 文本长度、换行和可读区域。

每次规划会输出 `_sticker_plan.json`，便于审计具体证据和跳过原因。

## 使用者反馈学习

脚本反馈示例：

```bash
python script_feedback.py \
  --video output/final/example_final.mp4 \
  --rule "字幕应该像带货文案而不是画面描述" \
  --verdict violated \
  --comment "这版只是在重复画面"
```

贴图反馈示例：

```bash
python sticker_feedback.py \
  --video output/final/example_final.mp4 \
  --plan-json output/final/example_sticker_plan.json \
  --sticker-id sticker-segment-3-origin \
  --rule "产地贴图不要遮挡主体" \
  --verdict violated
```

同一规则需要至少两个不同成片的明确使用者反馈后才成为 active 规则。自动质检、LLM 判断和参考视频分析不能创建或晋升用户偏好。

## 失败行为

严格模式下，以下情况会阻断不可发布成片：

- 视觉理解未启用或素材没有有效视频窗口；
- LLM 未返回完整、合法且通过合同校验的 segments JSON；
- 具体产品主张缺少相关 Evidence Anchor；
- 脚本要求的主体、动作或状态没有足够素材容量；
- 单条口播、字幕和语义镜头时间轴无法形成一致映射；
- 请求了口播但没有生成有效音频。

失败任务保留中间产物。不要通过删除证据校验或允许任意镜头兜底来绕过失败，这会重新引入字幕与画面错位。
